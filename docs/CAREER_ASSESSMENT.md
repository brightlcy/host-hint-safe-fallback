# What this portfolio demonstrates

This is an assessment of evidence in the repository, not a hiring prediction or claim of readiness for any specific vacancy.

| Audience | Supported evidence | Still unproven |
|---|---|---|
| Samsung DS / SK hynix storage and solution software | Page mapping, invalidation, greedy GC, WAF definitions, workload-dependent policy comparison, controlled validation and documented limits | Production C/C++ firmware ownership, controller resource constraints, NAND/ECC/PLP behavior, actual device debugging |
| FADU / SSD firmware teams | Placement-policy reasoning, counterexamples, immutable conditions, reproducible simulator experiments and a wear-balance trade-off | Real NVMe/FDP implementation, hardware-calibrated latency, performance under real queue/channel parallelism, independent firmware implementation |
| International systems/storage research | Clear questions, equal-resource comparisons, failed hypotheses, bounded claims, seed split discipline and historical result replay | Broad external validity, hardware deployment, proof of new general theory, independent coding skill or oral defense |
| Linux / AI infrastructure | Transferable experimental discipline and storage I/O performance reasoning | Linux kernel/driver contributions, GPU data-path work, distributed training/serving performance, production incident experience |

A useful next skills check is to explain one mapping/GC invariant, predict a small policy change, implement it independently, run the relevant tests and account for the outcome. Keep that new run separate from the frozen research. Rebuilding this repository alone does not establish that ability.
